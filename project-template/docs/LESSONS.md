# Lessons

<!--
HOW TO USE THIS FILE

The curated team record, promoted here at session end; personal working memory is separate and
automatic. Newest first, and live only: this file holds the lessons that still apply today. A
lesson is a rule that changes future behaviour. If it would not change what you do next time,
it is not a lesson; do not write it. Every entry here is read as currently true, so a lesson
that has been overtaken actively misleads the session that finds it. That is why the supersede
rule below is not optional.

- Write one after every correction from the user, without exception. That is the
  highest-signal input this project gets, and it is worthless unless captured immediately.
- Also write one after a wrong path you had to back out of, after something that worked
  notably better than the obvious approach, and after discovering an undocumented constraint.
- Check for a near-duplicate first. If one exists, MERGE into it and sharpen its mitigation
  rather than adding a second entry.
- Supersede, never overwrite. When a new lesson contradicts or replaces an old one, write the
  new entry first, then MOVE the old entry out into docs/lessons-archive.md, creating that file
  if it does not exist, with one line prepended to the moved entry:
  "Superseded YYYY-MM-DD by: <new entry title>". A lesson that no longer applies to the project
  as it is today moves the same way. Never delete an entry; move it.
- When a lesson has hardened into a standing rule, add a one-line entry for it in the
  project's CLAUDE.md as well. That file is read every session, so it holds a handful of rules.
- Do not read this file whole at session start. Search it for keywords relevant to the task.
- The title is an instruction, not a topic: "Agree the frame before synthesising", not
  "Synthesis issues". The mitigation must be something a future session can actually follow:
  "be more careful" is not a mitigation.
- Refer to people by role, never by name.

Entry format:

### <short imperative title>: YYYY-MM-DD
- **Context:** <the situation, one line>
- **What failed:** <what went wrong, or "n/a">
- **What worked:** <what actually helped>
- **Mitigation:** <the rule to follow next time: must be actionable>
- **Tags:** <comma, separated, tags>

Delete the EXAMPLE block once real entries exist.
-->
