# session-start

Read the installed Builder protocol and applicable native project instructions. The
user's existing task authorization persists through this ritual.

1. Retain a wrapper/hook identity if supplied; otherwise announce a two-word codename.
   Determine the absolute project root and declared memory backend before creating files.
2. **Files:** create only missing memory records in an authorized standalone project.
   Read STATUS in full and only the latest JOURNAL entry. Search DECISIONS, LESSONS and
   RESEARCH for the current task's keywords. Codex uses project AGENTS.md; Claude uses
   CLAUDE.md (which may point to the same AGENTS.md). Preserve existing instructions.
3. **Collective:** verify actual birth-block content, not just headings. Fetch missing
   brief/checkpoint content with the absolute repo and correct audience. Load matching
   packs. Reuse the registered session and wrapper bindings; only register if needed.
   Discover the actual MCP schema rather than inventing arguments. Never scaffold file
   memory on this branch. If MCP is unavailable, report the missing context/persistence
   and do not switch backend or restart a shared stack from a worker.
4. Inspect relevant task ownership and changed files. An in-progress task alone is not
   evidence of abandonment. Leave active owners alone; reconcile only your own work or
   work demonstrably abandoned and authorized for takeover.
5. Report codename, loaded sources, backend, last checkpoint, blockers and next action.
   Register/claim the task before edits. Continue an already requested task; if the user
   asked only for orientation, report the recommendation without inventing new work.

After compaction, reload authoritative state and continue the same task and identity.
